# 드래그 앤 드롭 포커스 대상별 동작 정의서

## 개요
칸반 카드에서 드래그 앤 드롭 시 포커스하는 대상(메인 카드 vs 서브태스크 항목)에 따라 다른 동작을 수행해야 합니다.

## 현재 구조 분석

### 1. KanbanCard 구조
```
┌─ 메인 카드 영역 (draggable="true") ─────────────────┐
│ ┌─ 체크박스 + 제목 + 핀 버튼 ─────────────────────┐ │
│ │ □ 태스크 제목                            📌   │ │
│ │ 2024-01-01 ~ 2024-01-10                      │ │
│ └─────────────────────────────────────────────┘ │
│ ┌─ 서브태스크 목록 영역 ───────────────────────┐   │
│ │ 서브태스크 (2)                            │   │
│ │ ├─ 서브태스크 1 제목               [DOING] │   │
│ │ ├─ 서브태스크 2 제목               [TODO]  │   │
│ └─────────────────────────────────────────────┘   │
└───────────────────────────────────────────────────┘
```

### 2. 현재 문제점
- 전체 카드가 `draggable="true"`로 설정되어 있어 서브태스크 항목을 클릭해도 메인 카드가 드래그됨
- 서브태스크 개별 드래그가 불가능한 상태

## 요구사항 분석

### Case 1: 메인 카드 영역 드래그
**포커스 대상**: 메인 카드의 헤더 영역 (제목, 체크박스, 핀 버튼 등)

**동작**:
1. **드롭 대상이 컬럼인 경우**:
   - 메인 태스크의 상태 변경 (TODO ↔ DOING ↔ DONE)
   - 서브태스크들은 메인 태스크를 따라 이동하지 않음 (독립적 유지)

2. **드롭 대상이 다른 카드인 경우**:
   - 현재와 동일: 메인 태스크를 드롭된 카드의 서브태스크로 변경
   - 검증: 메인 태스크에 서브태스크가 있으면 거부

### Case 2: 서브태스크 항목 드래그
**포커스 대상**: 서브태스크 목록의 개별 서브태스크 항목

**동작**:
1. **드롭 대상이 컬럼인 경우**:
   - 서브태스크를 메인 태스크에서 분리 (parent_task_id = null)
   - 독립적인 메인 태스크로 승격
   - 지정된 컬럼의 상태로 변경

2. **드롭 대상이 다른 카드인 경우**:
   - 서브태스크를 현재 부모에서 분리
   - 새로운 부모 카드의 서브태스크로 이동

## 기술적 구현 방향

### 1. 드래그 영역 분리
```tsx
// 메인 카드 - draggable 속성 제거
<li className="..." /* draggable 제거 */>

  {/* 메인 카드 헤더만 draggable */}
  <div
    className="..."
    draggable="true"
    onDragStart={(e) => onDragStart(e, 'MAIN_CARD', ...)}
  >
    <!-- 헤더 내용 -->
  </div>

  {/* 서브태스크 개별 draggable */}
  <div className="subtasks-area">
    {subTasks.map(subTask => (
      <div
        draggable="true"
        onDragStart={(e) => onDragStart(e, 'SUB_TASK', subTask.id, ...)}
      >
        <!-- 서브태스크 내용 -->
      </div>
    ))}
  </div>
</li>
```

### 2. 드래그 데이터 구조 확장
```typescript
interface DragData {
  cardId: string;
  sourceColumnId: string;
  sourceProject: string;
  sourceTeam: string;
  dragType: 'MAIN_CARD' | 'SUB_TASK';  // 새로 추가
  parentId?: string;  // 서브태스크인 경우 부모 ID
}
```

### 3. 드롭 핸들러 분기 처리
```typescript
const handleDragEnd = async (e: DragEvent, ...) => {
  const { dragType, cardId, parentId } = dragData;

  if (dragType === 'MAIN_CARD') {
    // 메인 카드 드래그 로직
    if (dropTarget === 'COLUMN') {
      // 상태 변경만
    } else if (dropTarget === 'CARD') {
      // 서브태스크화 (검증 포함)
    }
  } else if (dragType === 'SUB_TASK') {
    // 서브태스크 드래그 로직
    if (dropTarget === 'COLUMN') {
      // 1. 현재 부모에서 분리
      // 2. 독립 태스크로 승격
      // 3. 새 상태로 이동
    } else if (dropTarget === 'CARD') {
      // 1. 현재 부모에서 분리
      // 2. 새 부모의 서브태스크로 이동
    }
  }
};
```

### 4. UI 피드백 개선

- 드롭 가능 영역 하이라이팅
- 드래그 중인 요소의 미리보기 커스터마이징

## 예상 사용자 시나리오

### 시나리오 1: 서브태스크 독립화
1. 사용자가 서브태스크 항목을 드래그
2. DOING 컬럼에 드롭
3. 서브태스크가 부모에서 분리되어 독립적인 DOING 상태 태스크가 됨

### 시나리오 2: 서브태스크 부모 변경
1. 사용자가 A 카드의 서브태스크를 드래그
2. B 카드에 드롭
3. 서브태스크가 A에서 분리되어 B의 서브태스크가 됨

### 시나리오 3: 메인 카드 상태 변경
1. 사용자가 메인 카드 헤더를 드래그
2. 다른 상태 컬럼에 드롭
3. 메인 카드만 상태 변경, 서브태스크들은 현재 부모 관계 유지

## 주의사항

### 1. 이벤트 전파 방지
- 서브태스크 드래그 시 부모 카드의 드래그 이벤트가 발생하지 않도록 `stopPropagation()` 처리

### 2. 접근성 고려
- 키보드 네비게이션 지원
- 스크린 리더 사용자를 위한 aria-label 설정

### 3. 성능 최적화
- 드래그 가능한 요소가 늘어나므로 이벤트 리스너 최적화 필요

### 4. 데이터 일관성
- 서브태스크 이동 시 부모-자식 관계의 데이터 일관성 보장
- 백엔드 API 호출 순서 고려 (분리 → 이동)

## 구현 완료 내용

### ✅ 메인 카드와 서브태스크 드래그 영역 분리
- 전체 카드의 `draggable` 속성 제거
- 메인 카드 헤더만 드래그 가능하도록 수정
- 서브태스크 개별 항목을 각각 드래그 가능하게 구현
- 이벤트 전파 방지로 의도치 않은 드래그 방지

### ✅ 드래그 타입별 데이터 구조 확장
- `dragType: 'MAIN_CARD' | 'SUB_TASK'` 추가
- `parentId` 필드로 서브태스크의 부모 정보 전달
- 하위 호환성을 위한 `isSubTask` 필드 유지

### ✅ 드롭 핸들러 분기 로직
- `handleDragEnd`에서 `dragType`에 따른 분기 처리
- 서브태스크 드래그 시: 부모에서 분리 → 독립 태스크로 승격
- 메인 카드 드래그 시: 기존 동작 유지 (상태 변경)

### ✅ UI 피드백 및 사용자 경험 개선
- 드래그 시작 시 시각적 피드백 (투명도 변경, 회전 효과)
- 서브태스크 hover 효과 추가
- 툴팁으로 드래그 기능 설명 제공
- 부드러운 transition 효과 적용

### ✅ 검증 및 테스트

3. 다른 카드에 드롭하면 부모 변경
